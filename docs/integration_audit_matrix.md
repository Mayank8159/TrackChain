## 1. Executive Summary: The Integration Architecture

The TrackChain system operates on a strict **Edge-to-Cloud** pipeline. The ML layer runs on the edge device (Raspberry Pi 5 / Jetson), processes high-rate sensor streams, and emits standardized `tc.v1` signals. The Backend layer ingests these signals, persists them to TimescaleDB/S3, and serves them to the Frontend SCADA dashboard.

## 2. The 5 Pillars of Synchronization

### Pillar 1: Contract & Schema Sync (`tc.v1`)
**The Rule:** The ML layer and Backend layer speak the exact same language.
- **ML Side:** `ml/core/schema.py` defines `CalibratedSignal`, `SegmentDecision`, `DefectClass`, `SignalType`.
- **Backend Side:** `backend/src/schemas/*.py` defines Pydantic models mirroring the ML dataclasses exactly.
- **Verification:** `test_signal_contract.py` confirms that `CalibratedSignal` generated by the ML pipeline can be serialized to JSON and deserialized by the Backend schema without data loss or type mismatch.

### Pillar 2: Calibration & Threshold Sync
**The Rule:** All 5 ML models output probabilities on the normalized `[0.0, 1.0]` scale, where `0.50` universally means "action threshold crossed."
- **YOLO & Bi-LSTM:** Calibrated via Temperature Scaling ($T$).
- **PatchCore & Seq-VAE:** Calibrated via Sigmoid Distance Mapping ($P_{99}$).
- **Physics:** Calibrated via Normalized Exceedance Ratio ($\text{Measured} / (2 \times \text{Limit})$).
- **Verification:** `test_calibration_sync.py` verifies that a score of `0.60` from YOLO and a score of `0.60` from Physics both trigger `fired=True` and are handled identically.

### Pillar 3: Media & Evidence Sync (S3)
**The Rule:** The ML layer uploads heavy binary video and images directly to S3/MinIO via presigned URLs and passes the `s3_key` to the Backend.
- **Verification:** `test_video_streaming.py` and `test_e2e_integration.py` prove that uploaded videos are transcoded into adaptive HLS streams (`1080p`, `720p`, `480p`, `360p`) and served back via master playlists.

### Pillar 4: Spatial & Temporal Sync (Chainage)
**The Rule:** All data is indexed against physical track distance (Chainage).
- **Spatial Grid:** Centerline distance is discretized into `0.25m` bins by `ml/core/chainage.py`.
- **Verification:** `test_integration_sync.py` proves that visual defects and geometry faults at the same chainage map to the exact same track segment and fuse cleanly.

### Pillar 5: Security & Auth Sync
**The Rule:** Edge pipelines authenticate as registered devices.
- **Verification:** `test_auth_and_security.py` confirms registration (`POST /api/v1/devices/register`), token exchange (`POST /api/v1/devices/token`), token bucket rate limiting, and HMAC-SHA256 request verification.

## 3. Schema & Mapping Taxonomy

### 3.1 ML Output → Backend Input Mapping

| ML Output (Python Dataclass) | Backend Schema (Pydantic) | Database Column (TimescaleDB) |
|---|---|---|
| `CalibratedSignal.name` | `MLSignalSchema.model_name` | `ml_signals.model_name` |
| `CalibratedSignal.signal_type` | `MLSignalSchema.signal_type` | `ml_signals.signal_type` |
| `CalibratedSignal.value` | `MLSignalSchema.calibrated_score` | `ml_signals.calibrated_score` |
| `CalibratedSignal.raw_score` | `MLSignalSchema.raw_score` | `ml_signals.raw_score` |
| `CalibratedSignal.threshold` | `MLSignalSchema.threshold` | `ml_signals.threshold` |
| `CalibratedSignal.fired` | `MLSignalSchema.fired` | `ml_signals.fired` |
| `CalibratedSignal.label` | `MLSignalSchema.label` | `ml_signals.label` |
| `CalibratedSignal.bbox` | `MLSignalSchema.bbox` | `ml_signals.bbox` (JSONB) |
| `CalibratedSignal.explanation` | `MLSignalSchema.explanation` | `ml_signals.explanation` (JSONB) |

### 3.2 Signal Type Routing

| Signal Type | Source Model | Dashboard Visualization | Severity Logic |
|---|---|---|---|
| `VISUAL_KNOWN` | YOLOv8n | Bounding box overlay on video frame | Direct from confidence |
| `VISUAL_NOVEL` | PatchCore | Heatmap overlay + anomaly marker | Requires persistence ($\ge 3$ consecutive) |
| `GEOMETRY_KNOWN` | EN 13848 Physics | Telemetry graph exceedance threshold line | Direct from exceedance ratio |
| `GEOMETRY_KNOWN_TYPE` | Bi-LSTM | Typed fault label on telemetry graph | Inherits from GEOMETRY_KNOWN |
| `GEOMETRY_NOVEL` | Seq-VAE | Reconstruction error spike graph | Requires persistence ($\ge 3$ consecutive) |
